7. Deliver a new aggregate JSON/Markdown report and a go/no-go recommendation for B vs C. ## Phase B: conditional implementation design, not yet authorized

Only after A's results and author approval: introduce a separate storage-format version, while retaining mr1 arithmetic/version; share immutable public metadata and use tested codecs/adapters at every reader. Inventory Check/Create/draft replay, Join, Python audit, public values, dashboard/list/member popover, phase transitions/vote tally and task snapshots. Search all consumers of mr1_evidence/social_links/relevance_scores/isr_scores/participants; inline legacy histories continue through their existing path. Keep capacity failure before publication and idempotent duplicate checks. Include real SDK byte/operation limits and document limits for new copies and Join, not only Create.

For memory, design paged profile/vector evaluation with stable document-ID ordering, retaining no raw vector arrays after a page. Separate direct A discovery, outgoing A relationship processing and one-public normalization. Keep all B eligibility, including zero additions and maximum qualifying source/no second hop. Preserve original A/B encounter order or prove identical floating-point reduction: current normalization uses stored rounded R/E, not newly rounded/asynchronously summed alternatives. Exact population digest, age date, values aggregation and malformed/missing-vector refusal remain. Scratch state may be needed; its ownership, lifecycle and capacity must be part of the approved design, not hidden writes. A fixed immutable allowlisted source copy is recommended for initial emulator parity. Dynamic live-source freshness requires a later enforced revision/snapshot contract; a preflight hash alone is not a transactional lock on all profiles.

## Phase C: fallback logical publication design, separate decision

If physical atomic commits cannot fit, propose immutable build generations: absent/staging -> validated/ready -> active by a small final transaction. Byte-bounded chunks may be prepared before activation, but every root/list/member/tally/Join consumer must resolve the same active generation. No partially visible scores or mixed-generation means. The final transaction rechecks draft/context/date, authoritative source epoch, duplicate-title registry and single idempotent creation result. Stale/conflicting builds never activate; retries resume verified chunks, not paid AI calls. Define CAS/lease ownership, crash recovery, cancellation, retention and bounded orphan cleanup. Newly written staging data must not trigger normal lifecycle actions. Existing open prototype rules cannot be assumed to hide/secure staging data; rules/access changes require an explicit spec/approval before deploy. Freeze policy for voting and concurrent Join/phase/creator operations must be specified. No schema collection choice is approved here.
