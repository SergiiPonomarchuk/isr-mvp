# M3 review-stage integration impact proposal

Status: **design proposal, not authorized for implementation or deployment**. The offline stage fixture does not replace the current Analyzer.

- Effective decision resolution needs its own reviewed contract for new inputs: status, chosen decision, affected facts, exact quotes, clarification precedence and genuine contradictions. The current fixture origin string/hash is not authentication and must never be accepted as proof of an author's approval from a client/model. Do not silently settle arbitrary inputs or choose a reference scope to obtain pass.
- Extract the existing compatibility predicate into a shared production module only with full parity tests; retain scope provenance. Candidate projection must preserve all original chain IDs/scores, with explicit scope_rule versus model_domain origins. Do not add a top-k or alter alpha/weight/member formulas.
- Version prompt/wire/rule/decision records separately from unchanged scoring version. Actual model results need model/prompt/input/schema/source metadata; fixture_only records cannot be published. Preserve original input/clarification, immutable effective decision, ranking/library binding, exact domain response and all explicit verdicts. New metadata must not imply v3/v4/v5 observations ran under a new protocol.
- Update Check/Create/draft validation and cache keys together. Unfinished drafts with obsolete contracts require a fresh Check; completed historical creation replay, published issues and Join retain their frozen contracts/scores. No historical issue migration/rescore or bulk embedding is proposed. No Firestore rules or security/auth changes are implicitly authorized.
- Prove refusal on unresolved/contradictory/stale decisions, changed plans, missing domain rows, partial scope proofs, forbidden reason types, forged fixture origins and duplicate IDs. Add real handler/emulator parity and human UI acceptance before deployment. A model can still produce false context reasons or scope facts, so source matching alone cannot authorize publication.
- Review every persisted source/proof reference and the verbose fixture's 124 KB footprint against Firestore per-document/transaction/request limits, including existing population score/vector data. Deduplication must preserve reconstructible immutable provenance. Existing full-population memory/capacity gates remain open; no cap/threshold adjustment or storage redesign is implicitly authorized.
- Any UI change must show meaningful unresolved facts or actual reference gaps, not implementation metadata. Keep personal-help eligibility and explicit clarification authority. Do not present a deferred domain review as ineligibility or an accepted public.
- Keep application models, embedding templates, saved selection text and reference library unchanged unless separately specified. An actual stage check has its own precise counted allowance; no 23rd request or automatic embedding/regeneration follows from this document.

Before integration, obtain approval of a focused task spec and execute required Node/Python suites, handler/emulator checks, storage-envelope proof and author human judgment. Deploy and every production mutation remain author-only steps.
