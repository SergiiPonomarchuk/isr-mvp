## Exact experimental schema

Format publication_version=c2b-emulator-1; scoring_version=fixture-supplied-v1. Logical C1 generation tokens retain build_id/manifest_hash/epoch/member_count. Physical issue/discussion/public roots are raw snake_case application-shaped records, not C2a wrappers: publication_version,fixture_id,logical_key,issue_id,public_id,build_id,manifest_hash,epoch,member_count,title/topic,description,status,phase,phase_revision,ends,creator_uid,context_summary plus options_revision,votes_revision,management_revision,tasks_revision,conversation_revision and round/outcome references when applicable. No persisted legacy full score/participant maps. Metadata/parser rejects unknown/malformed format. Private records use version/fixture/key plus JSON typed payload preserving key order/numeric bits/Unicode/dates.

Use precisely the approved section6 c2b physical namespaces. Logical private commands/state is a bounded mutable control with revision, option/message refs, choices(votes/management), current task/outcome refs, round token and phase/status/deadline controls. commands/{operation_id} stores binding/status/completion receipt; immutable content/outcomes use outcomes/{operation_id}/nodes/{node}, control contains typed artifact manifest/seal/source bindings. Field/order hashes are canonical where Firestore maps can reorder; original typed artifact order remains unchanged. Unsealed immutable content never enters a visible root reference. Each state mutation compares current generation/phase/relevant revisions and immutable complete input, then commits roots/control/receipt together. Replayed operation never applies twice.

Initial generation preparation uses C1 begin/stage/seal. Activation augments its captured pure write set with bounded application headers in the same real transaction. Join preserves current mutable state and advances publication mirrors/revisions consistently. Precomputed successors add only the two allowed UIDs. Source/catalog/day guards and per-job budgets remain; restart cannot seed missing authority. Fixture catalogs derive only validated published roots from an explicit finite fixture registry, include revision/complete coverage and date binding. No collection scans or real profiles.

Content paging: options/messages/tasks/outcomes may be segmented into typed nodes before publication. Private outcome metadata binds input/generation/revisions and deterministic node IDs; stage/checkpoint writes are byte/work bounded. Final writes publish small validated references, not whole member/outcome payloads. Existing codec64KiB artifact/64-record/512-node bounds remain. Counts/text maxima are admission ceilings intersected with all byte/work guards, not a promise every Cartesian combination fits. Oversized unsplittable logical input refuses before changing visible records; no truncation. Preserve published artifacts/replay indefinitely in this experiment.

Command envelope: version,fixture_id,command,args; mutation args bind operation_id,actor_uid,expected publication token and relevant revisions, user choices/content only. Server loads/validates complete selected membership; no caller weight/winner/input paths. Pure Lifecycle/ISR decisions use original enumeration and rounding. Prepare tally/tasks outside final transaction, seal artifact, recheck token and vote/options/phase revisions atomically; ToDo only with complete outcome. Ordinary choices use current generation after Join; voting round pins its generation. Controlled clocks/fault hooks are trusted in-process tests only, never JSON.
