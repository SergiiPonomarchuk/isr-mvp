## Plan and behavior

1. Review context using one bounded structured model response, all raw-chain candidate metadata and exact actual input/context. Pin mr1-context-review-1, library/model/task/template and exact source spans. Retained references have reasons and map to at most3 evidenced actual-issue aspects (a resource bound, not a reference cap or a judgment of complexity); more required analysis returns an internal analysis-limit service result, not a forced user split. Every excluded candidate has a reason. Questions depend on missing facts, never chain count alone. Numeric weights/geography/CBC come from recorded references, not free model edits. Existing source/category discrepancies remain literal recorded reference IDs; no hidden taxonomy aliases.
2. Compute every candidate's D/G/S/E in bounded vector-read chunks, with no early D/G/top300/top100 exclusion. Use the core's inclusive .15 A, unconditional eligible-relative B and full-addition source ceiling. Eligible edges use explicit finite ties or the existing named spouse/parent/child/sibling/grand/close-friend map; additional explicit family aliases (aunt/uncle/niece/nephew/cousin/in-law) remain eligible with0 default tie. Unknown untyped/no-tie links are reported, not guessed. All required profiles/vector metadata/skills/birthDate must be available; fail rather than silently excluding unknown data.
3. Store only immutable scoring model/aspect vectors, input/day/population fingerprints and small preview in the checked draft. Recompute and verify population identity at Create without provider calls. Cross-day drafts require a new Check so registration-date scoring cannot drift. Clarification edits invalidate drafts. Old published issues keep legacy scoring/Join; unfinished legacy drafts require a new Check; completed-draft replay stays idempotent.
4. New Create publishes issue/vector/public/member/discussion/message and draft result atomically through the existing duplicate registry. Preflight actual serialized document/request sizes against Firestore limits; capacity failure returns an explicit error before writes, never truncation. Cache maps/participants include all A/B; preserve creation/result/task metadata. Registration time is actual successful Create time on the same checked day. Store member raw/effective/cohort/source evidence and freeze A outgoing source links for subsequent explicit Join.
5. Explicit discussion Join evaluates the person's R/E under the issue's frozen mr1 aspect/model and existing A sources, without adding another social generation; normalize over enlarged public. Unknown version rejects rather than silently using legacy math. Legacy unversioned issues retain legacy joining. Current endpoint caller/auth semantics remain until D2; do not claim userId is authentication.
6. Add clear context-answer input, question/error display and stale-response/draft invalidation to the existing create modal; preserve main.js CRLF plus final CR. New Check is strict model/context analysis; old analyzeIssue suggestions remain diagnostic, cannot create a draft. No keyword fallback may be labelled a reviewed mr1 pass; this follows the approved context prerequisite. Logging failure retains existing best-effort analyzer_logs behavior, while valid model provenance/draft is mandatory. No new rules.

## Implemented contract and limits

- Runtime pins `mr1-context-review-1`. The primary retained reference supplies the compatibility category; every retained reference keeps title/classification/domain, actual evidence, weights, similarity/alpha and aspect mapping. Domain display includes all retained domains. The old p4/five-example suggestion endpoint remains diagnostic only.
- Check has one text-review request. Embeddings: one whole-issue text, one additional selection text when clarification is present, and 1–3 deduplicated actual-aspect texts. Create/Join use no provider calls. Retries are governed by the existing embedding helper; no new paid evaluation allowance was used. Full population scans and values reads are intentionally larger than legacy shortlists. Check/Create have a bounded 300-second timeout. Full 9,150-profile runtime and real-model quality are not established by the small synthetic fixtures.
- Unsupported no-tie relation types are ignored with an aggregate `ignored_untyped_links` diagnostic stored on the draft/returned at Check; supported family zero-tie links remain eligible. Employment criteria use only the implemented any/employed/unemployed choices; student/retired criteria are refused rather than silently treated as any. Soft-D and other PD-1 changes are separate.
- Member preview is bounded to 25 rows, but count, score normalization, server values aggregation and published membership use all A/B. Viewer badges show their actual member scores or “Not a member”. Whole-public values parity is verified with a member outside the preview.
- Capacity uses SDK protobuf serialization and documented storage sizes, with safety margins, for every proposed document and request before atomic publication/Join. It intentionally rejects oversized uncapped publics. This is not a promise that every population-sized public fits a single request. Population identity is verified at recomputation; profile editing is not locked across the database while publication commits. Existing synthetic fixtures are stable. Authentication/authorization stays D2 work.
- The independent `scripts/mr1_check.py` reads projected profiles/vectors, recomputes actual-aspect evidence and A/B membership, applies the one age floor and canonical normalization, and reports only mismatch identifiers/fields. `check_demo.py` dispatches mr1 scenarios to it; legacy D1 remains on legacy arithmetic. This is a current-data audit: later profile/vector edits can produce legitimate drift reports; frozen issue/member records are never migrated by the checker.
